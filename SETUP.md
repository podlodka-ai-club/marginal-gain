# Подключение памяти к своему агенту

Для того, кто видит проект впервые. От клона до первой подсказки — минут
пятнадцать, читать исходники не нужно. Как всё устроено внутри — `README.md`,
как работать в самом репозитории — `AGENTS.md`.

Что получится: перед ответом агенту подставляется несколько фактов из прошлых
разговоров, а конец каждого хода дописывает в базу новые. Ничего никуда не
уходит: база это файл SQLite на вашей машине, ни ключа, ни сети.

## Как выключить

Первым, до всего остального. Точки заняты в настройках агента и срабатывают в
каждом разговоре, в любом проекте, — значит выключатель нужен раньше, чем
включатель:

```bash
./bin/xmem live off        # заглушить все хуки везде
./bin/xmem live on         # вернуть
```

Насовсем — убрать блок `hooks` из настроек агента, шаг 3. Совсем начисто —
раздел «Убрать без следа» в конце.

## 1. Поставить

Нужны python 3.11 и git. Сторонних пакетов у контура нет, он на стандартной
библиотеке; пакеты из `requirements-dev.txt` нужны только проверкам.

```bash
git clone git@github.com:podlodka-ai-club/marginal-gain.git
cd marginal-gain
cp .env.example .env
python3 -m pip install -r requirements-dev.txt
python3 -m storage.db migrate
python3 -m pytest -q
```

Всё дальнейшее зовётся из корня клона. Точки входа — модули (`python3 -m
pipeline.suggest`), запуск файлом не работает.

## 2. Открыть ворота

Ворота закрыты по умолчанию: пока каталог не назван живым, хуки молчат везде.
Установка, включающая себя сама, включается и там, где её не звали.

```bash
./bin/xmem here add        # сделать текущий каталог живым, подкаталоги тоже
./bin/xmem                 # всё состояние: что включено и откуда взято
```

Вторая команда — главный прибор в этом проекте. Она печатает `память здесь:
живая` или `молчит` и рядом с каждым рубильником называет источник значения:
умолчание, файл или переменная окружения. Окружение сильнее файла, и
`XMEM_BACKEND`, выставленный когда-то в `.zshrc`, молча отменяет любую вашу
правку — это видно только здесь.

Память нужна не только в этом клоне. Каждый рабочий каталог добавляется той же
командой из него самого.

## 3. Занять точки в настройках агента

Хуки написаны, но зовёт их агент, а не репозиторий. Пока точки не заняты,
контур не работает — и выглядит это ровно как исправный контур, которому нечего
сказать.

Открыть `~/.claude/settings.json` и вписать блок `hooks`. Путь до клона свой:

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {"type": "command", "command": "~/dev/marginal-gain/hooks/on_prompt_queue.sh"},
          {"type": "command", "command": "~/dev/marginal-gain/hooks/on_prompt_read.sh"}
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {"type": "command", "command": "~/dev/marginal-gain/hooks/on_stop.sh"}
        ]
      }
    ],
    "MessageDisplay": [
      {
        "hooks": [
          {"type": "command", "command": "~/dev/marginal-gain/hooks/on_message_display.sh"}
        ]
      }
    ]
  }
}
```

Три правила, каждое стоило дня:

* **Если `hooks` в настройках уже есть — дописать группы к своим точкам, ничего
  не стирая.** Чужие напоминалки в тех же точках работают дальше.
* **Звать только файлы из `hooks/`.** Они проходят через `common.sh`, где
  ворота и окружение. Хук, зарегистрированный мимо, работает во всех проектах
  сразу.
* **После правки перезапустить агента.** Настройки читаются на старте.

Что заняли и зачем:

| Точка | Кто зовётся | Зачем |
|-------|-------------|-------|
| сообщение человека | `on_prompt_queue.sh`, `on_prompt_read.sh` | положить ход в очередь и подставить память в запрос |
| конец хода агента | `on_stop.sh` | разобрать разговор и записать эпизоды, факты, связи |
| печать ответа | `on_message_display.sh` | срезать с экрана служебный блок разметки |

Первые две обязательны. Третья косметическая: без неё человек будет видеть в
ответах служебный блок `<<<MEMORY-FACTS`, разбор при этом работает.

## 4. Проверить, что память отвечает

База пустая, вспоминать нечего. Положим пробный факт — он же уйдёт вместе с
базой, когда надоест:

```bash
python3 - <<'PY'
from domain import models
from storage import db
repo = db.Repository()
repo.apply([models.Fact(
    fact_type="project_state", scope="project",
    subject="/home/person/шкаф/db.py",
    content="В проекте demo правился файл /home/person/шкаф/db.py ради задачи: почини",
).mutation()])
repo.close()
PY
```

Теперь спросим тем же путём, каким спросит агент, — тем самым хуком и с тем же
входом:

```bash
echo '{"prompt": "какие файлы правились в проекте demo"}' | ./hooks/on_prompt_read.sh
```

Ожидаемый ответ. Первой строкой хук печатает просьбу к модели разметить факты
— она уходит в тот же запрос и нужна для записи; следом идёт то, ради чего всё:

```
В конце ответа, последним блоком, поставь разметку фактов: …
Из памяти прошлых разговоров:
- В проекте demo правился файл /home/person/шкаф/db.py ради задачи: почини
```

Есть блок — подключено. То же самое в живом разговоре: спросите агента про
проект demo, и эти строки уедут к нему до того, как он начнёт отвечать. Дальше
факты копятся сами: конец каждого хода разбирает разговор.

## Если тишины

Хук молчит и в разговоре, и при поломке: ошибка не идёт ни в ответ, ни в
stderr агента. Снаружи одинаково выглядят три разных случая — пустая точка,
закрытые ворота и исправный хук, которому нечего сказать. Различать их по
порядку:

1. **`./bin/xmem`** — говорит `память здесь: молчит`? Ворота закрыты, шаг 2.
   Говорит `живая ли память off`? Кто-то выключил, `./bin/xmem live on`.
2. **Настройки агента** — точка занята? Команда в ней ведёт в существующий
   файл? Запись, ведущая в пустоту, молчит так же, как её отсутствие.
   Проверяется прогоном `python3 -m pytest tests/test_live_wiring.py -q`.
3. **Журналы** в `~/.local/state/memory-encoder/`:

| Файл | Что в нём |
|------|-----------|
| `suggest.log` | ошибки чтения: почему не пришла подсказка |
| `queue.log` | ошибки очереди на сообщении человека |
| `save.log` | ошибки конца хода: разбор, факты, связи, забывание |
| `suggest-log.jsonl` | что спрашивали и сколько строк прошло порог |

Пусто во всех трёх, точки заняты, ворота открыты — значит хук отработал и
промолчал по делу: подходящего в базе не нашлось или не хватило веса. Сколько
нашлось и сколько прошло порог, видно в `suggest-log.jsonl`.

Отдельно частое: `не задан XMEM_INSTANCE_ID` в журнале означает, что выбран
сетевой путь наружу. Живому контуру он не нужен, `./bin/xmem backend local`.

## Убрать без следа

```bash
./bin/xmem live off
```

Дальше — убрать блок `hooks` из настроек агента, удалить каталог состояния
`~/.local/state/memory-encoder` (там очередь, база и журналы) и сам клон.
Больше проект нигде ничего не держит.
