# Памятка агенту

Проект пишет память из живых разговоров. Хуки заняты в настройках агента и
срабатывают в каждом ходе, поэтому первое, что надо знать, — как их выключить.

## Рубильники

Всё переставляется одной командой; она же показывает, откуда взято значение.

```bash
./bin/xmem                 # состояние целиком
./bin/xmem live off        # заглушить все хуки во всех проектах
./bin/xmem here add        # сделать текущий каталог живым
./bin/xmem backend local   # ход пишет в SQLite (умолчание), sdk — в xmemory
./bin/xmem marks show      # показывать служебный блок на экране
./bin/xmem scheme xmd1     # схема разметки: просьба и маппер парой
./bin/xmem memory long     # режим памяти: сколько факт верен без обращений
```

Окружение сильнее файла и потому сильнее команды — на один запуск:

```bash
XMEM_LIVE=0 …          # заглушить, XMEM_LIVE=1 — включить
XMEM_BACKEND=sdk …     # путь наружу
XMEM_HIDE_MARKS=0 …    # показать служебный блок
XMEM_MARKS=xmd1 …      # схема разметки
XMEM_MEMORY=short …    # режим памяти: short, normal, long
XMEM_HOOK_SECONDS=10   # срок чтения в горячем пути
```

Порядок силы: окружение сильнее файла, файл сильнее умолчания. Полная таблица
и доводы — в `README.md`, раздел «Переключатели».

## Что где лежит

| Где | Что |
|-----|-----|
| `~/.local/state/memory-encoder/queue.jsonl` | очередь: что положил хук на сообщении человека |
| `~/.local/state/memory-encoder/save-state-<путь>.json` | докуда разобран архив сохранением, своя отметка у каждого хранилища |
| `~/.local/state/memory-encoder/understand-state-<путь>.json` | докуда разобран архив пониманием, тоже своя у каждого хранилища; при `XMEM_DISABLED` путь называется `off` |
| `~/.local/state/memory-encoder/save.lock` | замок на проход по архиву, общий у очереди и понимания: база одна |
| `~/.local/state/memory-encoder/live-projects` | ворота: где память живая. Понимание на конце хода сужено до архива названного проекта |
| `~/.local/state/memory-encoder/suggest.log`, `save.log`, `queue.log` | ошибки хуков; в разговор они не попадают |
| `~/.local/state/memory-encoder/suggest-log.jsonl` | что спрашивали и сколько прошло порог |
| `~/.local/state/memory-encoder/memory.db` | локальная база |

Хук молчит и в разговоре, и при поломке. Если кажется, что память не работает,
смотреть journalы выше, а не гадать: пустая точка, закрытые ворота и исправный
хук, которому нечего сказать, выглядят снаружи одинаково.

## Правила работы в этом репозитории

1. **Хук зовётся через `common.sh`.** Там ворота, окружение и корень. Хук,
   зарегистрированный мимо, минует ворота и работает во всех проектах сразу.
2. **Отметка о прочитанном принадлежит хранилищу.** Меняешь путь наружу —
   проверь, что курсор идёт за ним, иначе один контур закрывает архив другому.
3. **Зелёный тест — не доказательство.** Сломать проверяемое и убедиться, что
   тест краснеет. Проверки живого контура особенно легко пустеют: на закрытых
   воротах хук молчит, и любое утверждение про его работу проходит.
4. **Ход человека — горячий путь.** Всё, что дольше миллисекунд, уходит в фон
   или под срок.
5. **Срок факта ставит одна функция.** `domain.lifespan.until`, и вид отметки
   у неё один. Просроченное отбирается сравнением строк в SQL: разойдись
   формат — сравнение соврёт молча, и часть записей уедет в отложенное живой, а
   часть останется в выдаче мёртвой. Забытое не удаляется, а перекладывается в
   `LapsedFact`; достать его можно глубоким чтением.
6. **Внешний формат разметки знают двое: просьба и маппер.** Оба лежат одной
   записью в `marks.SCHEMES`. Появилось поле снаружи — правится маппер, схема
   `domain/models.py` не двигается: `Association.source_key` адресует факт
   строкой `fact_type|subject|scope`, и смена ключа рвёт все связи.
7. **Блок разметки человеку не показывают.** В этом харнессе за это отвечает
   точка `MessageDisplay` (`hooks/on_message_display.sh`), в своём обвесе —
   `marks.strip` и `marks.Tail`. Молчание хука значит «печатай как было»:
   испорченный вывод виден в каждом разговоре, поэтому при любой поломке
   лучше не тронуть ничего.

## Запуск на чужой машине

Нужен python 3.11 и git. Сторонних пакетов у контура нет — он написан на
стандартной библиотеке; пакеты нужны только проверкам.

```bash
git clone git@github.com:podlodka-ai-club/marginal-gain.git
cd marginal-gain
cp .env.example .env            # для local ни ключа, ни сети не надо
python3 -m pip install -r requirements-dev.txt
python3 -m storage.db migrate   # создать локальную базу
python3 -m pytest -q            # 430+ зелёных
./bin/xmem                      # состояние рубильников
```

Живой контур этим не включается: хуки зовёт агент, и точки заняты в его
настройках, а не в репозитории. Как их занять — `SETUP.md`, памятка для того,
кто подключает память к своему агенту впервые. Пока каталог не назван живым, хуки молчат:

```bash
./bin/xmem here add             # сделать текущий каталог живым
```

### Через docker

Образ поднимает локальную базу и гоняет проверки на машине, где не настроено
ничего. Живой контур в контейнере не работает и работать не должен — агент
запускается снаружи.

```bash
docker compose up db            # схема в томе xmem-state; выходит с нулём — норма
docker compose run --rm tests   # проверки в том же образе
docker compose run --rm shell   # консоль: ./bin/xmem, python3 -m storage.db counts
```

База — SQLite, файл `/state/memory.db` в томе `xmem-state`. Сервера у неё нет:
путь наружу `local` выбран затем, чтобы не держать ни сети, ни ключа, ни квоты.
Поэтому `db` — не демон, а разовый прогон миграций, повторять его безопасно.

## Проблемы запуска, которые уже встречались

Каждая ниже выглядела как поломка кода, а была настройкой окружения.

1. **`ModuleNotFoundError: pipeline`.** Точки входа зовутся модулями
   (`python3 -m pipeline.switch`), а корень репозитория в путь поиска кладут
   `bin/xmem` и `hooks/common.sh`. Запуск файлом (`python3 pipeline/switch.py`)
   этого не делает — звать через `-m` из корня репозитория.
2. **Переменная в профиле молча отменяет рубильник.** Порядок силы —
   окружение, файл, умолчание. `XMEM_BACKEND=sdk`, выставленный где-то в
   `.zshrc` или в образе, отменяет `./bin/xmem backend local`, и команда об
   этом честно пишет: `← окружение (XMEM_BACKEND)`. Смотреть эту колонку
   раньше, чем искать баг.
3. **Хук молчит и при поломке.** Ни в разговор, ни в stderr агента ошибка не
   идёт. Журналы: `~/.local/state/memory-encoder/{suggest,save,queue}.log`.
   Пустая точка, закрытые ворота и исправный хук выглядят снаружи одинаково.
4. **Ворота закрыты по умолчанию.** Нет `live-projects` — молчат все хуки во
   всех проектах. Это защита: установка, включающая себя сама, включается и
   там, где её не звали. Лечится `./bin/xmem here add`.
5. **Проверки живого контура пропускаются, если настроек агента нет.**
   `tests/test_live_wiring.py` читает `~/.claude/settings.json` и соседей. Нет
   ни одного файла — класс уходит в skip: в свежем клоне подключать нечего.
   Файл есть, а точка пуста — остаётся красным, это и есть поломка.
6. **Узел файла в контейнере переиспользуется.** На overlayfs удалённый и
   заново созданный файл архива получает прежний `st_ino`, и подмена выглядит
   как дописывание: разбор шёл не с начала. На APFS такого не воспроизвести —
   проверка зеленела у автора и краснела у всех остальных. Поэтому отметка
   помнит ещё и начало файла (`understand.head_of`), а не только узел с
   размером.
7. **`XMEM_INSTANCE_ID` нужен только сетевым путям.** У `local` ни ключа, ни
   идентификатора нет. Если запись падает на «не задан XMEM_INSTANCE_ID» —
   значит выбран `sdk` или `api`, см. пункт 2.
