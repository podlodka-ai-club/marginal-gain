# Памятка агенту

Проект пишет память из живых разговоров. Хуки заняты в настройках агента и
срабатывают в каждом ходе, поэтому первое, что надо знать, — как их выключить.

## Рубильники

Всё переставляется одной командой; она же показывает, откуда взято значение.

```bash
./bin/xmem                 # состояние целиком
./bin/xmem live off        # заглушить все хуки во всех проектах
./bin/xmem here add        # сделать текущий каталог живым
./bin/xmem backend local   # ход пишет в SQLite (умолчание), sdk — в xmemory
./bin/xmem marks show      # показывать служебный блок на экране
./bin/xmem scheme xmd1     # схема разметки: просьба и маппер парой
```

Окружение сильнее файла и потому сильнее команды — на один запуск:

```bash
XMEM_LIVE=0 …          # заглушить, XMEM_LIVE=1 — включить
XMEM_BACKEND=sdk …     # путь наружу
XMEM_HIDE_MARKS=0 …    # показать служебный блок
XMEM_MARKS=xmd1 …      # схема разметки
XMEM_HOOK_SECONDS=10   # срок чтения в горячем пути
```

Порядок силы: окружение сильнее файла, файл сильнее умолчания. Полная таблица
и доводы — в `README.md`, раздел «Переключатели».

## Что где лежит

| Где | Что |
|-----|-----|
| `~/.local/state/memory-encoder/queue.jsonl` | очередь: что положил хук на сообщении человека |
| `~/.local/state/memory-encoder/save-state-<путь>.json` | докуда разобран архив сохранением, своя отметка у каждого хранилища |
| `~/.local/state/memory-encoder/understand-state-<путь>.json` | докуда разобран архив пониманием, тоже своя у каждого хранилища; при `XMEM_DISABLED` путь называется `off` |
| `~/.local/state/memory-encoder/save.lock` | замок на проход по архиву, общий у очереди и понимания: база одна |
| `~/.local/state/memory-encoder/live-projects` | ворота: где память живая. Понимание на конце хода сужено до архива названного проекта |
| `~/.local/state/memory-encoder/suggest.log`, `save.log`, `queue.log` | ошибки хуков; в разговор они не попадают |
| `~/.local/state/memory-encoder/suggest-log.jsonl` | что спрашивали и сколько прошло порог |
| `~/.local/state/memory-encoder/memory.db` | локальная база |

Хук молчит и в разговоре, и при поломке. Если кажется, что память не работает,
смотреть journalы выше, а не гадать: пустая точка, закрытые ворота и исправный
хук, которому нечего сказать, выглядят снаружи одинаково.

## Правила работы в этом репозитории

1. **Хук зовётся через `common.sh`.** Там ворота, окружение и корень. Хук,
   зарегистрированный мимо, минует ворота и работает во всех проектах сразу.
2. **Отметка о прочитанном принадлежит хранилищу.** Меняешь путь наружу —
   проверь, что курсор идёт за ним, иначе один контур закрывает архив другому.
3. **Зелёный тест — не доказательство.** Сломать проверяемое и убедиться, что
   тест краснеет. Проверки живого контура особенно легко пустеют: на закрытых
   воротах хук молчит, и любое утверждение про его работу проходит.
4. **Ход человека — горячий путь.** Всё, что дольше миллисекунд, уходит в фон
   или под срок.
5. **Внешний формат разметки знают двое: просьба и маппер.** Оба лежат одной
   записью в `marks.SCHEMES`. Появилось поле снаружи — правится маппер, схема
   `domain/models.py` не двигается: `Association.source_key` адресует факт
   строкой `fact_type|subject|scope`, и смена ключа рвёт все связи.
6. **Блок разметки человеку не показывают.** В этом харнессе за это отвечает
   точка `MessageDisplay` (`hooks/on_message_display.sh`), в своём обвесе —
   `marks.strip` и `marks.Tail`. Молчание хука значит «печатай как было»:
   испорченный вывод виден в каждом разговоре, поэтому при любой поломке
   лучше не тронуть ничего.
