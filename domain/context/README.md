# Модуль уместности

Уместность — насколько факт подходит к тому, что происходит прямо сейчас.
Рядом с весом («знание это или мусор») она второй множитель: до агента доходит
то, где высоко и то, и другое. Без неё память отдавала частое вместо
подходящего — факт про правку файла в одном проекте всплывал, когда работаешь
в другом.

Модуль делает три вещи:

1. **Приводит обстановку к общей форме.** Обстановку хода (payload хука) и
   обстановку факта (поля эпизода, с которым факт связан) сводит одна функция
   `of`. Одна на обе стороны — иначе сравнивать нечего.
2. **Считает уместность** — число от 0 до 1 от совпадения двух обстановок.
   Порог применяется к произведению веса на уместность.
3. **Даёт срезы по обстановке.** «Все факты проекта», «все факты вторника»,
   «факты вторника и проекта» — это один механизм с разным набором осей.
   Спросить так раньше было нельзя вовсе.

```bash
python3 -m storage.db signals                       # полный список признаков
python3 -m storage.db slice --project X --day tuesday
```

## Что здесь принято

| Утверждение | Основание |
|---|---|
| Уместность и вес — два разных множителя, а не одна оценка | ADR 0009; обзор: «признаки веса и уместности разделены» (Generative Agents, Zep, PlugMem), [research 8](../../research/research-8-contextual-relevance.md) |
| Гейт двухфазный: сперва кандидаты на полноту, потом фильтр на точность | так уже устроено (поиск словами → отсев → порог, ADR 0006 и 0008); [research 8](../../research/research-8-contextual-relevance.md) подтверждает, что это общая практика |
| Структурные признаки (место, время, связи) стоят того, чтобы делать их первыми | [research 8](../../research/research-8-contextual-relevance.md): снижают шум на 18–35% против чистой похожести |
| Правило отбора — вес × уместность, плюс порог, плюс top-K, плюс бюджет символов | ADR 0009; обзор перечисляет четыре правила с их минусами и заключает, что сочетание работает лучше одного |
| Обстановка факта берётся связью `episode_facts`, а не колонкой в факте | ADR 0009. Обстановок у факта несколько (он встречался не раз), колонка оставила бы последнюю |
| Единица оценки — атомарный факт, а не сообщение целиком | так уже устроено (ADR 0004); [research 8](../../research/research-8-contextual-relevance.md): хранение сессии одним элементом ухудшает поиск |
| Полный список признаков заводится сразу, реализуется по одному | требование интента. Молча отсутствующий признак неотличим от забытого: [`signals.py`](signals.py), 21 признак, 5 сделано |

## Не измерено

Отдельным разделом, потому что цифры ниже выглядят как решения, а решениями не
являются. Ни одна не проверена замером на отложенном окне.

- **Веса пяти осей** (0.55 / 0.15 / 0.15 / 0.1 / 0.05). Выведены не из данных,
  а из правила «проект решает, остальное уточняет»: сумма четырёх остальных
  меньше порога, вес проекта — больше. Правило взято из наблюдения.
- **Порог уместности 0.5** (`suggest.MIN_FIT`). Взят с потолка, под него же
  подогнаны веса.
- **Часть суток — четыре часа.** Взято с потолка. Час в час совпадал бы почти
  никогда, сутки целиком — почти всегда; четыре — середина без обоснования.
- **Затухание соседа по графу 0.5** (`suggest.DAMPING`, ADR 0006). Взято с
  потолка ещё тогда, числом не обосновано. Обзор называет расстояние в графе
  отдельным признаком уместности — у нас затухание постоянное на любом
  расстоянии, и шаг ровно один.
- **Потолок в пять кусков** (`suggest.MAX_ITEMS`) **и 1200 символов**
  (`MAX_CHARS`). Взяты с потолка. Обзор даёт для них внешнее подтверждение
  общего толка (Lost-in-the-Middle, Context Length Alone: избыток контекста
  ухудшает ответ даже при идеальном извлечении), но не числа.
- **Прирост качества от уместности.** Не замерен вовсе. Есть только проверка
  ожидаемого сигнала: тот же вопрос, другой проект — факта нет.

## Чего здесь намеренно нет

- **Близости по смыслу (embedding).** Требует модели или сети, а хук чтения
  стоит в горячем пути под сроком в 10 секунд. Ограничение снимается локальным
  индексом, а не выбором модели.
- **Дельта-гейта** («обстановка не менялась — память не трогаем»). Интент
  разрешал делать, только если даётся даром. Не даётся: нужно состояние между
  ходами, то есть ещё один файл в `~/.local/state` со своей книжкой учёта. Это
  оптимизация, а не смысл работы.
- **Смены схемы факта.** Ветка, каталог и время добираются связью. Колонка в
  факте читалась бы быстрее, но обстановок у факта несколько.
- **Двух шагов по графу и переменного затухания.** Как и было в ADR 0006.
- **Различения «человек сказал» и «агент вывел».** Обзор называет `source`
  обязательным полем единицы памяти. У нас его нет: маппер разметки получает от
  модели `source` и `confidence` и выбрасывает оба — они работают фильтром на
  входе и до хранилища не доезжают. Предикат и значение он же склеивает в
  `content`. Пока это так, уместность судит текст целиком и не может отличить
  сказанное от выведенного. Схему под это не трогали — отдельная работа.
- **Остальных четырнадцати признаков** из [`signals.py`](signals.py). Каждый
  помечен «не сделано» и назван вместе с тем, откуда его брать и что мешает.

## Чем проверяется

| Что | Где |
|---|---|
| Форма одна на обе стороны: одна минута, описанная payload'ом хука и записью эпизода, даёт один словарь | `tests/test_relevance.py`, `TestOneShapeForBothSides` |
| Уместность лежит в 0…1, симметрична, монотонна по осям; факт без общих осей уместен везде | `TestTheFitIsANumberBetweenZeroAndOne` |
| «Проект решает, остальное уточняет» — арифметика самих весов, а не выдача на примерах | `TestTheRegistryIsTheSourceOfAxes.test_the_numbers_say_the_rule_out_loud` |
| Порог судит произведение веса на уместность | `TestTheThresholdJudgesTheProduct` |
| Ожидаемый сигнал: тот же вопрос в своём проекте и в чужом | `TestTheSameQuestionInAnotherProject` |
| Знание про человека (охват `global`) не берёт обстановку у эпизода, с которым связано | `TestGlobalKnowledgeStaysUnbound` |
| Факт уходит структурой вместе с обстановкой | `TestTheFactTravelsWithItsContext` |
| Обстановка снимается без сети и без модели, ветка — чтением `.git/HEAD` | `TestTheSituationCostsNothingToTake` |
| Реестр признаков — источник осей и весов, несделанное видно | `TestTheRegistryIsTheSourceOfAxes` |
| Срезы комбинируются; срез по двум осям вложен в пересечение одиночных | `tests/test_slices.py` |
| Срез и уместность читают одну и ту же обстановку факта | `TestTheSliceAndTheFitReadOneContext` |

**Мутации, которыми проверялась непустота этих тестов** (каждая роняет
названное):

| Мутация | Краснеет |
|---|---|
| `context.fit` возвращает константу | `test_the_fact_shows_up_at_home_and_stays_away_elsewhere` |
| `suggest.place` ничего не приписывает | тот же плюс оба теста про обстановку в куске |
| `situation_of` берёт из payload один `prompt` | `test_the_hook_payload_gives_the_whole_situation` |
| `render` не печатает строку обстановки | `test_the_text_for_the_model_names_the_situation` |
| `context.matches` всегда истинна | два теста срезов |
| `Repository._situations` не читает связи | `test_every_fact_of_a_slice_really_has_that_axis` |
| глобальный охват не исключён из обстановки | оба теста `TestGlobalKnowledgeStaysUnbound` |

## Файлы

- [`__init__.py`](__init__.py) — форма, уместность, срез по осям, описание для модели.
- [`signals.py`](signals.py) — полный список признаков: сделанные с весами,
  остальные с пометкой «не сделано» и с тем, откуда их брать.
- Порог, отбор и подача — `pipeline/suggest.py`.
- Обстановка факта и срезы в хранилище — `storage/db.py`, `Repository.situations`.
- Решение целиком — [ADR 0009](../../docs/adr/0009-umestnost-fakta.md).
- Источник — [research 8](../../research/research-8-contextual-relevance.md).
