# Как решения по агентской памяти забирают данные из сессии

Собрано 2026-08-24. Ячейка либо заполнена по документации или коду, либо явно помечена "нет данных". Ссылки на источники внизу.

## Группа 1: платформы памяти

| Модуль | Mem0 | Zep / Graphiti | Cognee | Supermemory | MemOS (MemTensor) |
|---|---|---|---|---|---|
| Единица входа | последний обмен репликами плюс скользящее резюме и m последних сообщений | эпизод: сообщение, текст или JSON, хранится сырым как источник истины | документ или реплика через `add`, отдельно быстрый кэш сессии | документ, диалог, URL, PDF, картинка, таблица, видео | сообщение через `add/message`, также трассы инструментов и персоны |
| Триггер записи | вызов `add` в потоке приложения | вызов добавления эпизода | `add` плюс `cognify`, для сессии `remember(session_id=...)` | вызов API, дальше очередь | вызов API, планировщик MemScheduler |
| Синхронно или фоном | извлечение в запросе, обновление резюме отдельным фоновым модулем | нет данных о фоновом планировщике, ингест инициируется вызовом | кэш сессии синхронно, синхронизация в граф фоном | асинхронно, статусы queued, processing, done | асинхронно через MemScheduler, заявлена миллисекундная задержка |
| Извлечение фактов | LLM достаёт кандидатов, затем сущности и триплеты | LLM извлекает сущности и связи, отдельный промпт разрешения дублей | LLM строит граф знаний на шаге cognify | LLM извлекает сущности в режиме `memory`, режим `superrag` извлечение пропускает и дешевле в 5 раз | LLM, память как граф, не чёрный ящик эмбеддингов |
| Структурирование | факты плюс графовые триплеты | двухвременной граф: время события и время узнавания | граф знаний плюс сессионный кэш | чанки, эмбеддинги, профиль пользователя, граф | графовые кубы (MemCube), изоляция по проектам и пользователям |
| Дедупликация и конфликты | сравнение с top-s похожими, LLM решает ADD, UPDATE, DELETE, NOOP | ребро не удаляется, а помечается недействительным с даты | нет данных | по `customId`, различает дифф и дописывает только новое | правка памяти обратной связью на естественном языке |
| Забывание | через решение DELETE на обновлении, политики TTL нет данных | инвалидация по времени, история сохраняется | нет данных | нет данных | нет данных |
| Чтение | векторный поиск по фактам плюс граф | гибрид: граф, вектор, полнотекст | `recall` с автовыбором стратегии | поиск по документам и профилю | гибридный поиск |
| Оценка | заявлен прирост точности 26 процентов, LOCOMO | статья с бенчмарками DMR и LongMemEval | BEAM, заявлен SOTA на 100K и паритет на 10M | нет данных | LoCoMo 88.83, LongMemEval 89.20, лидерство в OmniMemEval, OpenClaw с 36.63 до 50.87 |
| Открытость | открытый код | открытый код Graphiti, Zep как сервис | открытый код | сервис, есть self-hosted | открытый код плюс облако |

## Группа 2: то, что живёт прямо в кодовом агенте

| Модуль | Letta (MemGPT) | MemoraX Code | claude-mem | kcp-memory | xmemory (их плагин) |
|---|---|---|---|---|---|
| Единица входа | новые сообщения основного агента | выбранные инструкции пользователя и финальный ответ агента из доверенных ходов | реплика пользователя, каждый вызов инструмента, финал сессии | строки транскрипта и события вызовов инструментов | ничего не переносится автоматически |
| Триггер записи | каждые N шагов основного агента | завершённый ход, автоматический writeback | пять хуков: SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd | асинхронное сканирование после вызова инструмента | SessionStart подгружает контекст, PreCompact напоминает агенту записать самому |
| Синхронно или фоном | фоновый sleep-time агент, отдельный от основного | фоном | HTTP с таймаутом 2 секунды и без ожидания, работу делает воркер | фоном, демон | запись делает агент своими инструментами в ходе разговора |
| Извлечение фактов | второй агент переписывает блоки памяти | извлечение переиспользуемого знания из хода | воркер сжимает наблюдение через Claude Agent SDK, на Stop собирает структурное резюме | извлечения нет, только индексация | извлечение на стороне сервиса при записи |
| Структурирование | блоки памяти в контексте плюс архив | четыре вида: инженерная, репозиторная, личная, процедуры | SQLite плюс векторная база, поля резюме: запрос, что исследовано, что понято, что сделано, следующие шаги | SQLite с полнотекстовым поиском FTS5 | схема XMD пользователя, объекты и связи |
| Дедупликация и конфликты | агент сам переписывает блок | нет данных | идемпотентная вставка INSERT OR IGNORE | индексация по сессии и файлу | первичные ключи схемы |
| Забывание | консолидация архива силами агента | нет данных | нет данных | нет данных | нет данных |
| Чтение | блоки в контексте, поиск по архиву | поиск через скилл и CLI, автоподстановка по умолчанию выключена | внедрение контекста хуком SessionStart | MCP инструменты и CLI поиск | MCP инструменты, чтение на естественном языке |
| Оценка | нет данных | участник лидерборда, своих цифр в репозитории нет | нет данных | нет данных | своя статья с бенчмарками |
| Открытость | открытый код | плагин открыт, ядро только по API | открытый код | открытый код | плагин открыт, сервис закрыт |
